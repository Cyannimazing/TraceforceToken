| Result | Required interpretation |
| --- | --- |
| Transfer | Receipt-backed movement between addresses, not necessarily a purchase or sale |
| Native funding | First observed qualifying top-level funding within the declared examined range |
| Evidence-linked group | Connected observed edges, not people or common control |
| Early accumulation | Earliest observed window under the stated rule, not a verified launch/insider label |

| Linked selling | Distinct previously linked wallets with qualifying sales inside the declared 600-second interval |
| Missing evidence | Unknown/partial/unexamined, never proof nothing occurred |

Each event-derived finding, graph edge, group, and timeline item must resolve to report evidence. A successful empty query supports only no matching observations inside its retrieved window. Errors, rate limits, unsupported routes and exhausted budgets cannot silently become zero, a current holding, a clean audit, or a safety verdict.

Normalized records carry chain, block number/hash, transaction identity/index, log/trace identity where applicable, timestamp, participants, asset/raw amount, and provider/method/observation time. Findings retain rule/version/parameters and citations. The report includes pinned range/finality, eligible/examined wallet counts, per-wallet funding coverage, warnings and model context omissions. ## Funding, links, and early observations

An optional Blockscout key enables bounded incoming native transaction discovery with RPC candidate verification. Explicit local SQD evaluation instead searches recipient-filtered indexed top-level transactions, validates contiguous page headers and first/end canonical anchors, and verifies positive candidates against RPC transactions, successful receipts and recipient code. Each verified block commits atomically, so a later recoverable failure preserves the earlier prefix. Complete means the declared indexed search window, not independently disproven index omissions or complete wallet history. Production-approved SQD access remains necessary before hosting that source.

Without a selected indexer, or when SQD fails before any verified block and RPC capacity remains, the keyless fallback searches one contiguous oldest prefix of full blocks for every eligible candidate, default 32 and configurable up to 256, within the token investigation window and shared call/deadline budgets. It does not spend a code lookup on every candidate before searching. Positive-value inbound transactions require successful matching receipts before recipient code is read at the pinned end block and transaction block. Only code-empty recipient observations are retained; a matching recipient with contract/delegated code at the pinned end is excluded from this adapter's scope.

Full blocks are committed atomically: a failed or interrupted block contributes neither staged funding records nor expanded searched bounds. After at least one fully verified block, coverage is partial until the entire declared window has been searched; reaching that end can make this bounded top-level search complete. If no complete block was examined, an attempted failed acquisition is unavailable and a search not reached remains not_examined. Identified out-of-scope contract recipients remain not_examined. Coverage does not prove EOA identity: a candidate with no successful positive inbound observation may never require a code read. Empty search results establish only no qualifying retained observations inside the examined bounds. Internal native transfers and lifetime-first funding remain not examined.

None of these paths establishes lifetime-first funding. Exchanges, bridges, distributors and other services can fund unrelated wallets. Known hub/pool/zero-address exclusions prevent ordinary infrastructure edges from becoming wallet-control groups; unknown public-service labels remain a limitation. A direct transfer also admits explanations such as payment, custody and distribution.

Early accumulation uses the earliest observed interval and exact observed flow. Without verified launch coverage, it cannot identify launch participants, snipers, insiders or token creators. Partial transfer coverage restricts derived claims rather than being converted into a current balance.

## Supported selling scope

The sale adapter accepts authenticated Base Uniswap v2/v3 single-pool transactions with successful receipts, supported direct/router paths, a decoded swap, and reconciled direct wallet-to-pool token outflow plus pool-to-wallet ERC-20 quote inflow. V2 buys retain exact consideration and token-receipt support; native-funded buys additionally require the official router, exact transaction value and WETH Deposit. Multihop, mixed protocols, smart-wallet paths, intermediate consideration and native-ETH sale unwrapping remain unclassified.

Linked-selling rules require at least two distinct wallets, qualifying non-hub funding/direct-transfer links before the earliest sale, and supported sales inside a rolling 600-second interval. Citation sets include prior links and complete sale proof. Similar timing alone is insufficient; later links cannot be backdated. Even a valid finding does not prove coordination, ownership, manipulation or malicious intent.
