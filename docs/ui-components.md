# TraceForce interface components

Updated: 2026-10-12. The investigation workspace uses Aceternity registry components installed through its [official CLI workflow](https://ui.aceternity.com/docs/cli), then adapted to TraceForce's evidence model, browser theme preference and security policy.

## Actual installation

```powershell
npx.cmd --yes shadcn@latest add @aceternity/background-beams @aceternity/tracing-beam @aceternity/glowing-effect @aceternity/moving-border @aceternity/bento-grid @aceternity/loader @aceternity/spotlight --yes
npx.cmd shadcn@latest add @aceternity/background-beams-with-collision --yes
```

`components.json` maps `@aceternity` to `https://ui.aceternity.com/registry/{name}.json`. This installs source files, rather than a monolithic Aceternity npm package. The registry added Motion and Tabler icons; the project also uses `clsx` and `tailwind-merge` for its `cn` utility. Exact installed dependency versions are recorded in `package-lock.json`.

Its unmodified CLI output, registry JSON and SHA-256 provenance are retained in `.artifacts/aceternity/background-beams-with-collision.{original.tsx,registry.json,provenance.json}`. The original installed source hash is `ef1b5d0b32cae6f127773efd227938673d7df5dd10fb61381494b1bb5de0aa54`. The installer created one component file and needed no dependency installation because Motion was already present.

Its export is `BackgroundBeamsWithCollision({ children?, className?, compact?, active? })`. The original moving-beam/collision/explosion idea is retained as a left optical emitter, green/blue beam packets and fixed targets with six deterministic particles per impact. Hero mode uses three beams; transparent compact mode uses two. Each cycle lasts at least 5.2 seconds, with no rapid flashing. An owned animation frame updates only SVG attributes; there are no geometry-polling intervals or unmanaged reset timers. Manual pause, reduced motion, `active=false`, offscreen observation and document visibility suspend it without jumping through missed collisions. The decoration represents neither scan progress nor findings.

## Design and evidence boundaries

The **2026-10-12 reference report revision** follows the inspected SWARM hierarchy in the existing TraceForce theme: a 1,196px report shell, square bordered identity/stage header, separate six-column market strip, approximately 1.55:1 graph/sidebar columns, sticky graph and stacked gauge/verdict/rules. Council, replay, groups, contract context and holders follow below. A dataset comparison exposes sources, time anchors, requested scope, completed ranges, retained events and distinct candidate-balance counts. The AI receipt exposes actual model/profile/grounding/context metadata. Scores and probabilities remain unknown where the evidence cannot support them. Full 61-scenario production-browser verification and four final report checks passed; dark desktop/mobile/landscape captures are under `.artifacts/traceforce-reference-parity/`. This is hierarchy/geometry parity, not a claim of identical source data or pixel-identical fonts.

The current concept is a robot diagnostic workspace: graphite or pale-gray surfaces, lime active signals, cold-blue secondary paths, restrained amber warnings and clear steel borders. Workspace viewport/manifest colors match the actual palettes (`#0a0c10` dark and `#eff2ed` light). Generated TraceForce assets provide consistent branding.

The subsequent compact-report revision follows the supplied reference holder screenshot: seven columns (#, Wallet, Float, Entry, Txs, Flags, Swarm), compact positive-balance rows, short lowercase badges and expandable proofs. A percentage falls back to explicitly labeled total supply when float exclusions cannot be verified. Txs uses acquired pinned outgoing nonce rather than silently substituting retained record counts. Wallet activity, funding, timeline, source limits and evidence remain available in disclosures. That revision displayed a supported upper bound/range and omitted uncalculated probability bars; the later numeric presentation below supersedes those two display choices. Groups remain observed links rather than identified people.

The latest **2026-10-12 compact numeric presentation** follows the three supplied sidebar screenshots: a numeric score ring with band and a brief holder/hands line; VERDICT OUTPUT with three slim decision-weight bars and the mass X-ray; and SCORE with six lowercase category names, slim bars, points/weight and short RULES TRIGGERED bullets. Each panel has one main Details disclosure for qualifications, policy, sources and evidence. Assessment 1.3.0 awards positive earned credits from disclosed local linear curves, sums exact decimal tenths and rounds the capped subtotal once. PARTIAL identifies incomplete assessed weight. Unassessed categories show 0 earned points without converting missing measurements or risk into absence; their underlying status and complete possible range remain inspectable. The reference's private category conversions and statistical performance are not established by visual similarity.

The bars use `traceforce-judge-1.0.0` normalized local rule weights, with displayed tenths totaling 100.0%. Known category deductions, unknown category weight and established earned points form the base avoid/caution/ok masses. Two local policy units preserve the deterministic verdict, and an authenticated hard dump warning adds its fractional modeled impact to avoid. These are transparent policy coefficients rather than calibrated event probabilities. The X-ray and receipt disclose the real calculation; calibrated confidence remains null. The [reliability record](reliability.md#assessment-display) specifies the equations and public-reference audit limits. Static semantic Tailwind classes and SVG numeric attributes preserve CSP, theme adaptation and keyboard disclosures.

Main holder values use 13px text with compact 44px rows. On small screens the seven-column table scrolls inside a keyboard-focusable region. Opening a flag aligns its readable proof box inside that region; evidence links retain keyboard access. The final mobile assertions check the complete badge and proof bounds, rather than only page overflow or proof width.

The bubble graph is a project domain visualization, not an Aceternity blockchain analyzer. Default Wallets uses exactly the Top holders population, denominator and one-decimal labels. Positive holding-circle area is proportional to verified balance divided by that denominator on one common scale, without a minimum radius exaggerating tiny holdings. All addresses restores contract and funding context with its explicitly disclosed broader denominator; selecting supplemental addresses reveals this view automatically. Zero, unknown and known infrastructure markers are unscaled, and unexamined funding sources are not presumed infrastructure. Invalid snapshots cannot establish balances. With no verified wallet rows, the graph discloses its All addresses fallback. The explicitly labeled flow fallback represents observed activity separately. Its 48-node pagination does not impose a collector wallet cap. Source-reported market/holder context remains distinct from transaction evidence; pool age is not token launch age. Native tables, evidence buttons and expandable details keep their keyboard semantics.

Colors follow `prefers-color-scheme`; there is no in-app theme switch, theme cookie, or theme storage. Motion follows `prefers-reduced-motion` and can be paused. Decorative effects do not create evidence, confidence, progress, scores, wallet ownership, or safety claims. Report source metadata remains visibly distinct from verified transaction evidence.

The production nonce CSP remains intact. Motion effects use SVG attributes and static Tailwind classes rather than allowing inline HTML styles. The report redesign passed lint, TypeScript, 381 unit tests, the production build and all 51 browser scenarios, including ordinary motion, reduced motion, theme/contrast changes, responsive layout, chat lifecycle, source attribution and evidence navigation. The later collision-laser/home integration also passed the complete lint/TypeScript/381-unit check and production build; its expanded browser verification is pending.
