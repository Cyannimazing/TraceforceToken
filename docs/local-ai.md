# TraceForge Engine investigator agent

Every completed investigation requires actual **TraceForge Engine Investigator** inference through the configured local, OpenRouter or Gemini provider. Profile **1.6.0** selects existing finding/caveat references and writes a short natural explanation in `summary.text` using at most two selected structured decision reasons. Action, verdict, source, findings and complete proof remain separately canonical; the prose is model-authored commentary, not a restored fixed sentence. Missing/invalid text, malformed references, cancellation or a deadline produces an error without a successful preset fallback. OpenRouter remains free-only by default. Reports stay in page memory unless the visitor explicitly saves or downloads them; no server report/chat history is created.

The opening action follows the report's explicit primary authority, matching its gauge and verdict: AVOID becomes “Avoid for now,” CAUTION/REVIEW becomes “Be careful,” OK becomes “No major warning found,” and INSUFFICIENT becomes “Not enough information.” New SWARM-led reports preserve one source assessment and separately label independent blockchain checks. Generated summary prose explains selected source measurements, including strong creator-linked/largest-group shares when available, without inventing a reason from the source's private formula. Missing source data remains unavailable. Older absent-flag reports keep their original local authority, and profile1.5 summaries remain canonical-only.

The question panel uses a short-lived signed context returned with a fresh scan. **Every accepted chat turn invokes genuine configured-provider inference**, including greetings, thanks, identity questions and clarification. Substantive replies use authenticated scan facts, the current message and bounded recent conversation; conversational prompts omit chain facts. Separate user and AI bubbles show messages after submission. Each request sends at most the last three completed exchanges (six messages, 1,000 characters each, 8 KiB total). History is untrusted context, never blockchain evidence. Conversation remains in browser/request memory and is excluded from snapshots, downloads and server storage. Restored snapshots need a fresh scan for active chat.

The named Ollama model is **`traceforce-investigator`**, built from **`qwen3:4b-instruct-2507-q4_K_M`** and the versioned `on-chain-investigator` profile. This is **instruction specialization**, not fine-tuning, a newly trained model, or proprietary base weights. The base model generates language; our profile, supplied evidence, structured output, validation, and runtime limits define its investigator role. The model does not acquire chain data, call tools, write to the database, or change the deterministic report.

The main-review context now chooses complete proofs jointly across the four investigation perspectives, with bounded deterministic shortlists. A dossier distinguishes retained events from supplied facts, explicit omissions, pinned candidate balances and source-reported metadata; transaction aliases preserve shared receipts. A genuine four-goal synthetic inference with the revised context passed in **67.506 seconds**, retaining all eight evidence records and four perspectives. This is one desktop selection/grounding check, not a general accuracy, speed or SWARM comparison. ## Conversational questions and evidence constraints

Questions and recent history pass bounded input and English directive checks. Recognized off-topic, override, secret, tool/execution and trading-advice requests reject without inference. Capsule authentication restricts explicit targets to the current token and retained addresses/hashes. Ordinary greetings, thanks, help, identity questions and context-free clarification receive short, genuinely generated replies after authentication, with no supplied chain facts or evidence citations. Model failure returns an error, not a canned successful greeting. These checks do not prove resistance to all prompt injection, obfuscation or other languages.

All substantive funding, connection, accumulation, selling, coverage, methodology and unknown-fact answers invoke the configured AI provider. Selected canonical findings constrain allowed factual claims and citations; they are not returned as preset answer prose. The application restores complete original proof, including sale support. Missing findings stay unknown. The model must not invent absence from omitted facts, quote balances absent from its supplied context, or treat previous assistant text as evidence.

The model has no tools or fresh acquisition. For substantive answers, the provider schema guides generation to two short sentences within 500 characters and a caveat within 180; compatible response limits remain 1,000/300 characters and four model aliases expanded to at most twelve complete references. Conversational replies use a separate short-answer schema with no citations and an empty caveat. Oldest history can be removed to preserve space for the current question and signed facts. Invalid output, unsupported citations, timeout or unavailable inference produces an honest error. Structural and lexical checks do not prove semantic accuracy.

Local main review normally uses one model request. If its finding selectors and complete citations validate but its generated summary fails semantic grounding, one summary-only regeneration may use the same model, selected source reasons, original deadline and cancellation signal. It cannot alter the original finding selectors or reason order. Malformed JSON, invalid citations, transport errors and cloud responses never enter this correction; a second invalid summary fails. Chat does not use this correction. Ordinary source-guidance chat generates one source-attributed sentence within 240 characters and a snapshot caveat within 140, using canonical positive risk meanings without percentages. Clarifications receive those meanings without repeated verdict priming; the full signed verdict and validation remain unchanged. Explicit measurement questions retain their signed values and scope. Missing concrete reasons cannot become invented sale or concentration warnings.

Inner main, correction and chat JSON rejects duplicate decoded property names, excessive nesting and malformed data before schema validation. This prevents silent last-value overwrites; it does not add a generation retry.

## Explanation and authority

Profile **1.5.0** retains bounded, fully supported deterministic finding selection rather than a prefix of transactions. The context builder jointly chooses complete finding portfolios from deterministic shortlists, favoring represented perspectives, story relevance and shared proofs. It supplies at most one finding per category. Every selected finding's entire original evidence-ID set is retained; every selected sale includes its token/quote supporting flows. The default 12-record cap permits a minimal linked-selling proof with two sales and a prior link, which needs seven records. It does not guarantee that every larger finding fits.

Selection also enforces the unchanged 8,000-byte model-context budget and a 20-original-citation cap per finding. It never trims a proof to make a finding fit. Findings omitted because of category diversity, the evidence cap, byte budget or citation cap remain in the current-page deterministic report. Their reason counts and per-category supplied/omitted counts appear in both context and explanation limitations. If no finding fits, a small proof-complete overview sample can still be supplied; it creates no observation packet. Invalid retained sale support or an already truncated finding rejects before inference.

Full normalized records and exact decimal-string amounts remain unchanged in the in-memory report. The model receives compact, deduplicated source facts containing event kinds, block numbers/timestamps, directions, asset roles and sale protocol/pool/support aliases, alongside the selected finding statements and caveats. It receives no duplicate raw ledger. Normal requests write no acquisition archive or saved evidence. Token names and arbitrary visitor prompts are not sent. Context strings are data, never instructions.

Only the first four distinct general coverage warnings of at most 500 characters are supplied without truncation. Generated per-wallet funding-status lines are summarized by the exact status counts instead; omitted-warning counts include those lines, duplicates, overlength warnings and other unsupplied warnings. A bounded retrieval-failure cause remains available even when many wallet lines precede it. The structured schema is sent once through Ollama's `format`, OpenRouter's `response_format.json_schema` or Gemini's `responseJsonSchema`; the user message contains a compact output-key hint instead of a duplicate schema. This keeps input bounded without raising the deadline or dropping retained evidence references.

Each request assigns **E1, E2, ...** aliases to supplied records, **F1, F2, ...** references to complete findings, and finding-local **C1, C2, ...** caveat references. The model reviews every supplied finding and its proof, returns one observation selector per finding, chooses one of that finding's caveats, and may reorder the observations. With findings present, it selects one or two F references for overview focus and leaves overview E references empty. Without findings, it selects up to two E references for a canonical evidence-kind summary; only an evidence-free context permits no overview references. Unknown, duplicate, omitted or mismatched references reject. No observation can substitute a shorter citation list.

The application restores the selected finding's canonical claim, exact indexed caveat, category and full proof. The published overview restores selected canonical statements or evidence-kind summaries, followed by exact coverage. A compact local decision packet supplies action, short request-local `R1`/`D1`/`D2` selectors and canonical human wording without duplicating the long report/token/block-hash binding in model input or output; complete source/proof metadata is restored and validated after inference. The model selects no more than two supplied decision reasons. Main review shortens repeated funding/source definitions while retaining every selected finding, caveat, proof fact, coverage statement and omission count; signed chat keeps its full bounded source context. Presentation abbreviates source addresses and formats token amounts; exact originals remain in the report. No model-authored claim, caveat, overview text or interpretation field is accepted by the strict selector schema. Canonical fork-specific IDs and transaction/block hashes stay out of model input; returned explanations use original IDs. Overview citations include complete selected evidence support and every observation's full proof, within the supplied context.

The model does not rerun investigation rules or create new findings. Only `summary.text` accepts generated prose: at most 400 characters in one/two sentences, attributed to the named source and checked against selected reason values/units, direct topic claims and missing-state/ownership/safety/prediction limits. No eligible findings means no observations. A transfer alone cannot establish a purchase, and a single sale cannot create a linked-selling finding. Completed reports require genuine inference, valid summary text and complete proof selectors; model failure has no successful fixed-text fallback.

Computed source facts give stable address-role labels, so repeated senders and recipients remain visibly identical. Canonical funding coverage separately reports complete, partial, unavailable and not-examined counts. Eligible wallets missing a coverage row remain not examined. Not examined means not checked; unavailable means history could not be retrieved. A completed bounded search is neither a positive funding event nor complete lifetime history. Native ETH funding and ERC-20 transfers remain distinct. The model cannot replace those meanings with a paraphrase or turn a possible infrastructure explanation into a published observed mechanism.

## Local-only operation and hosting

Set `INVESTIGATOR_AI_PROVIDER=local` and configure `LOCAL_AI_MODEL` for explicit local-only operation. With `auto`, leave both cloud API keys blank to retain local-only selection. Ollama's local API requires no paid API key. However, localhost alone does **not** prove local computation: Ollama can route cloud models through its local API. Explicit cloud model tags are rejected here, but custom aliases/proxies cannot be audited by this adapter. Disable cloud features on the **Ollama process** using `OLLAMA_NO_CLOUD=1` or its documented server setting, restart that runtime, and confirm its configuration. Setting this variable only in Next.js does not configure an already running Ollama server. Keep Ollama bound to loopback. ## Provider selection and OpenRouter setup

For OpenRouter in local `.env.local` or the protected engine environment, set:

```dotenv
INVESTIGATOR_AI_PROVIDER=openrouter
OPENROUTER_API_KEY=YOUR_OPENROUTER_KEY
OPENROUTER_MODEL=openrouter/free
OPENROUTER_FREE_ONLY=true
OPENROUTER_ALLOW_DATA_COLLECTION=false
```

Replace the placeholder with your private key, then restart the app or engine. This explicit selection uses only OpenRouter and fails if its key is missing; it cannot fall back to a configured Gemini key. No separate `GEMINI_API_KEY` is required. An OpenRouter account/key is still needed for free requests. [API authentication](https://openrouter.ai/docs/api_reference/authentication), [Free Models Router](https://openrouter.ai/docs/guides/routing/routers/free-router).

`openrouter/free` selects a free model at random using advertised request-feature support. A catalog declaration does not guarantee an endpoint will accept strict JSON schema or produce a grounded answer. A specific available `namespace/model:free` can be selected instead to reduce model-selection variability. Availability, quality, latency and rate limits still vary; no eligible model or invalid evidence output remains an error. Successful report/answer metadata retains the actual served model. The interface displays TraceForge AI. [Router selection and response metadata](https://openrouter.ai/docs/guides/routing/routers/free-router), [current limits](https://openrouter.ai/docs/api_reference/limits).

With configured free-only OpenRouter, `auto` tries **local → free OpenRouter** and excludes Gemini, even if a Gemini key is present. Local inference remains optional. Otherwise `auto` retains the configured local → OpenRouter → Gemini order, so use explicit `openrouter` for the no-payment setup above. Only `UNAVAILABLE` or `TIMEOUT` permits another selected attempt; invalid JSON, unsupported citations, grounding failures and cancellation do not. Attempts share one deadline of at most 120 seconds, reserving time for remaining providers. Explicit `local`, `openrouter` or `gemini` uses only that provider. Direct Gemini is a separate opt-in, outside OpenRouter's free-only policy.

The OpenRouter adapter posts only to `https://openrouter.ai/api/v1/chat/completions`, sends its key in the Bearer authorization header, and requests strict `json_schema` output with `require_parameters: true` and `allow_fallbacks: false`. `data_collection` is `"deny"` by default, or `"allow"` only when `OPENROUTER_ALLOW_DATA_COLLECTION=true`. Free-only requests also set `max_price: { prompt: 0, completion: 0, request: 0 }`; unavailable free service cannot trigger paid fallback. Application validation and canonical restoration remain mandatory. Accepted model syntax does not prove schema/evidence compatibility. `openrouter/free` is the reviewed router exception; `:free` is the only accepted variant suffix. Other routers and URLs are rejected. [Structured outputs](https://openrouter.ai/docs/guides/features/structured-outputs), [price and provider filters](https://openrouter.ai/docs/guides/routing/provider-selection#max-price).

Paid OpenRouter use requires deliberate `OPENROUTER_FREE_ONLY=false` and a paid model selection. The free-only policy concerns model API charges, not hosting, network access or the cost of operating a local model. OpenRouter's account/rate restrictions still apply; reaching them produces an error rather than a purchase or paid-model switch.

Signed chat contexts bind to the configured router request scope. A follow-up may be served by a different compatible free model, while its answer records that actual model; signature, profile, expiry and evidence checks still apply. A previous paid-model context does not become valid merely because the free router is now configured.

OpenRouter and its selected downstream provider receive the bounded context, question and recent dialogue needed for the request. If the operator approves provider data use, set `OPENROUTER_ALLOW_DATA_COLLECTION=true` and restart. This permits providers that may retain prompts/responses or use them for training under their own policies. It changes OpenRouter routing only; free-only prices, strict schema, evidence guards and no paid fallback remain unchanged. The default/template stays `false`.

Some free endpoints, including NVIDIA endpoints encountered during testing, may also require the account's **Free model training** preference at [OpenRouter privacy settings](https://openrouter.ai/settings/privacy). The application flag does not change or confirm that account setting. Account training preferences are distinct from OpenRouter's own optional logging/use of inputs and outputs. [Provider policies](https://openrouter.ai/docs/guides/privacy/provider-logging), [OpenRouter data handling](https://openrouter.ai/docs/guides/privacy/data-collection).

Neither flag value is a **zero-data-retention guarantee**: this adapter does not require `zdr: true`. External terms, retention and billing remain separate from TraceForge's no-server-history policy. Hosted deployment remains unverified.

## Direct Gemini and chat latency

Direct Gemini is a separate opt-in: set `INVESTIGATOR_AI_PROVIDER=gemini` and `GEMINI_API_KEY` in `.env.local` for local execution or the protected engine environment, then restart. Its account/billing terms are separate from free OpenRouter. Explicit Gemini ignores other providers; `auto` excludes it whenever free-only OpenRouter is configured. The examples include a blank placeholder; no key is bundled. Vercel receives no inference credential. `GEMINI_MODEL` defaults to `gemini-3.5-flash-lite`; `gemini-3.8-flash` is also supported. The fixed Google HTTPS endpoint receives the key in `x-goog-api-key`, never the URL. Existing structured-output, canonical-finding, whole-proof and chat guards still apply. Metadata retains `gemini/<model>`; the interface displays TraceForge AI. [Models](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite), [structured output](https://ai.google.dev/gemini-api/docs/generate-content/structured-output), [thinking controls](https://ai.google.dev/gemini-api/docs/generate-content/thinking).

Gemini has not been verified against a real account/key in this change. Historical verification records above identify their actual local runtime and profile; they do not verify cloud-provider quality or latency.

`LOCAL_AI_KEEP_ALIVE_SECONDS=300` keeps Ollama weights warm between requests rather than unloading after every turn; the allowed range is 0-900 seconds, with zero retaining explicit unload behavior. It retains loaded model weights, not application report/chat history. Conversational turns request at most 160 output tokens, substantive replies at most 384, and main selectors at most 300 within the configured ceiling. Complete evidence proofs are preserved; oldest recent dialogue is the only chat content eligible for prompt-budget removal. Output budgets, compact selectors and warm weights may reduce latency but cannot guarantee a response time.

Enabling Gemini sends the bounded supplied public-chain context and current question/recent page conversation to Google. Conversational prompts omit chain facts. The application still stores no reports or chats server-side, but Google's service data handling and billing terms apply to that external request. Never put credentials or private information in questions. [Gemini API terms](https://ai.google.dev/gemini-api/terms).

To repeat the metadata-only local chat check without a paid API or persisted report/chat, run `node --conditions=react-server --import tsx scripts/verify-chat-latency.ts --run-local`. Two accepted desktop turns took 10.389s and 3.983s with the 160-token conversational budget and 300-second warm-weight setting. See [evaluation scope](ai-evaluation.md#local-conversational-latency-check-with-warm-weights); these are not a general speed or accuracy guarantee.
