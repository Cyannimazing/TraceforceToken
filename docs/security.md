# TraceForge Engine security and privacy boundaries

Reviewed: **2026-10-14**. Current operation is local and Base-only; these controls are not an audit, penetration test, or hosted security certification. Historical checks below retain their actual dates and scope.

## Public access and data lifetime

No account, wallet signature, payment, token holding, or visitor access key is required. A fresh scan streams to its requester and is not saved as a server job/report. Public runtime code writes neither evidence nor chat history to MySQL or disk. The transient report UUID is not an authorization credential or a saved-result locator.

Optional Save writes only a validated report to IndexedDB in that browser/origin. Limits are five snapshots and 20 MiB of serialized report data. Snapshots can be deleted or cleared; they contain public chain observations and the visitor's investigation choices, so a shared browser or same-origin script can access them. They are not encrypted or synchronized. Chat context/conversations are excluded. A loaded snapshot is historical and cannot authorize new chat.

The optional color-theme choice stores only `light` or `dark` under `traceforge-theme` in localStorage. It contains no scan, token, evidence or conversation. Theme storage denial leaves the page usable. The decorative network/crawler performs no provider requests and uses pointer positions only in page memory.

This policy applies to the new request path. Legacy database records and previously generated operator artifacts were not erased. Explicit verification scripts may write public-chain diagnostic artifacts; they are separate, deliberately invoked tools, not runtime scan storage. Hosting/proxy logs must not capture request bodies, capsules, authorization headers, or full responses. Operator infrastructure logging can otherwise undermine the intended lifetime boundary.

## Per-visitor burst protection and active scans

The five-per-hour public quota has been replaced by **30 scan/question requests per visitor per 30-second window**, shared across those two endpoints, and **one active scan per visitor**. A window starts with that visitor's first request, using DB UTC time. Distinct browsers receive separate allowances, including on localhost; tabs in the same browser share one visitor. Requests with a valid session consume burst capacity before body validation, including rejected or failed submissions. There is no hourly scan or question allowance.

A page GET initializes a signed, host-only `traceforce_visitor` cookie with HttpOnly, SameSite=Strict, Path=/ and a 24-hour lifetime; HTTPS adds Secure. API requests never mint identities. Missing, tampered, expired or duplicate cookies reject before database/provider access. Signatures and opaque counter keys use separate HMAC purposes; arbitrary forwarding headers cannot choose an identity. This is an anonymous browser session, not proof of a person or a wallet. Clearing cookies or creating new browsers can create new visitors; it cannot stop distributed automation by itself. Rotating RATE_LIMIT_SECRET also invalidates visitor signatures and signed chat contexts.

Migration `0003_visitor_admission` adds only opaque visitor keys, window/count/expiry and a temporary random scan-lease token/expiry. No IP, token parameter, report ID, evidence or conversation is stored. READ COMMITTED transactions lock only the visitor's primary-key row, so concurrent requests cannot overspend that visitor's burst capacity or acquire two scans. The 330-second lease spans the streaming response; completion, cancellation, disconnect, execution failure and a 300-second outer deadline release it. Token-conditional release cannot clear a newer replacement lease. A failed release leaves the bounded lease to expire. Bounded opportunistic cleanup excludes live leases. Old hourly tables/repositories remain solely for legacy compatibility and are unused by public scans/questions.

Same-origin checks reject cross-origin browser submissions. They are an abuse barrier rather than authentication: a nonbrowser client can supply headers. Quotas and process capacity are not complete denial-of-service protection.

The public question boundary applies English topic/directive heuristics after short-window admission. Recognized off-topic requests, instruction overrides, credential requests, tool/execution requests, personal portfolio allocations and price predictions return `OUT_OF_SCOPE`/HTTP 400 without inference. After signature validation, explicit token/address/hash references must belong to the current signed scan context. Ordinary buy/sell/risk questions about the current report reach genuine inference; a source verdict cannot certify safety, profit or trade execution. These lexical checks are deliberately limited; obfuscation, other languages, and subtler prompt injection are not proven blocked.

Application controls do not guarantee immunity to API abuse or DDoS. Hosted deployment still needs perimeter protection and capacity monitoring. Vercel documents automatic deployment DDoS mitigation and optional WAF rate-limit rules; this local implementation has not configured or verified a hosted firewall. [DDoS mitigation](https://vercel.com/docs/vercel-firewall/ddos-mitigation), [WAF rate limiting](https://vercel.com/docs/vercel-firewall/vercel-waf/rate-limiting)

## Runtime controls

| Boundary | Implemented limit |
| --- | --- |
| Scan input | application/json, streamed 2 KiB cap, strict address/block schema |
| Question input | 48 KiB cap; question ≤1,000 characters; signed capsule ≤32,768 characters |
| Engine capacity | At most three active operations and one shared AI slot per process |
| Time | Scan 270 seconds; provider/AI 120 seconds; separate proxy/question deadlines |
| Output | Validated report ≤8 MiB, stream ≤16 MiB, bounded frames and errors |
| Questions | Answer ≤1,000 characters, caveat ≤300; at most four model aliases, expanded to ≤12 complete evidence references |
| DB | Parameterized queries, lazy server-only pool, bounded connections/waiting, no automatic DDL |

Owned AbortController timers remain alive until completion and are disposed in finally. Cancellation propagates through acquisition/inference and releases capacity. A disconnect or restart loses work; there is no durable retry/resume guarantee.

## Protected engine and local model

On Vercel, missing SCAN_ENGINE_URL/SCAN_ENGINE_SECRET fails closed. Only a trusted HTTPS /scan hostname is accepted; credentials, query, fragment, and arbitrary paths are rejected. DNS preflight excludes private/prohibited destinations, redirects are rejected, and the proxy validates bounded streamed reports. This DNS check is not connection-level address pinning; reviewed domains and network egress policy remain necessary.

The standalone engine binds to loopback, accepts bearer-authenticated POST /scan and /ask, and has no database credentials. An operator-controlled HTTPS reverse proxy exposes only those protected paths. Keep engine port 8787 and Ollama port 11434 private. Infrastructure secrets are never visitor requirements.

Ollama stays loopback-only with cloud disabled, one loaded model/inference, two CPU threads, and zero GPU layers in the prepared layout. The investigator has no tools, signing, shell, downloads, arbitrary fetch, or database access. Token metadata, questions, and source text remain untrusted prompt data.

Main-report profile **1.6.0** requires genuine generated `summary.text` of at most 400 characters, bound to selected structured decision reasons by `summary.grounding.mode="source-grounded-prose"`. Action, verdict, source and reason metadata remain canonical; finding/overview sentences, caveats and complete citations retain canonical selection validation. Shared prose checks reject unsupplied numeric values/units, direct topic swaps, changed decision labels and common unsupported ownership/safety/prediction claims. These bounded lexical checks are not a semantic truth certificate. New SWARM-led reports keep one source snapshot for the primary assessment; independent blockchain observations remain separate. Missing source data stays unavailable, and missing/invalid model text remains an error without a successful fixed-text fallback. Legacy 1.5 summaries remain canonical-only; older profiles retain their original validation. No profile specializes or trains base weights, verifies a provider's private formula, or proves acquisition completeness and model accuracy.

Chat capsules authenticate compact report-derived facts with purpose-scoped HMAC-SHA256. Reported SWARM/GoPlus/DEX context stays distinct from receipt-backed local findings; signing does not verify provider claims. Assessment metadata shares an existing 4 KiB budget inside the 32 KiB envelope without reducing the 6 KiB event/proof budget. For explicit SWARM authority, compact SWARM context has priority and optional local assessment is omitted first when space is insufficient. The authority marker remains SWARM even when source context is missing/omitted; ordinary score/verdict/holder/market questions cannot substitute local points. Explicit independent/pinned/Alchemy questions use separately supplied local facts. Legacy absent-flag capsules retain local-first behavior. Guards check source-qualified scores/verdicts and canonical facts, without certifying every generated semantic claim or permitting model-created measurements, calibrated probabilities or ownership. Older capsules retain their source identity. Verification checks size/signature before JSON parsing, then version, expiry, profile/model, citation uniqueness and sale support. Capsules expire after 30 minutes, are readable rather than encrypted and can be replayed until expiry. Rotation invalidates them. No server replay registry or conversation history exists.

Every accepted chat turn invokes the configured AI provider, including greetings and clarification. Substantive questions use authenticated canonical facts and complete finding proofs; conversational prompts supply no chain findings and cannot add factual claims. Recent conversation is limited to six messages/1,000 characters each/8 KiB total and is quoted untrusted data, never factual authority. Recognized directives and foreign explicit targets in history reject. Missing or omitted facts remain unknown; unavailable/invalid inference returns an error rather than a preset successful answer. The browser displays a separate retry status without an assistant avatar or answer bubble; only completed replies enter recent conversation. Proof expansion preserves all selected original evidence, including sale support. No conversation is saved or included in snapshots/downloads. Lexical and citation guards do not prove semantic truth or complete injection resistance.

Output/citation checks cannot establish semantic truth or eliminate prompt injection. The **06:32 UTC** integrated answer falsely denied retained transfers and was rejected. After corrective fixtures and rebuilding, the **06:39:22.123 UTC** real question did not repeat that denial and correctly described no detected native funding in its window, but used loose wording about completed indexed searches. That wording must not imply complete wallet history or positive funding records. One reviewed answer does not establish broad faithfulness or injection resistance. Commentary remains non-authoritative; unknown or omitted observations must not become absence, ownership, coordination, safety or investment advice.

## Provider and browser boundaries

The explicit network registry enables Base chain 8453 only. An unsupported network rejects before provider acquisition; another service advertising additional chains does not enable them in TraceForge. Adding a network requires its own validated acquisition adapter, contract/protocol identities, proof rules and tests.

Full-crawl scope is a validated enum, never a visitor-supplied start block, source URL or credential. Its requested token range begins at Base genesis; only fully processed ranges enter `coverage.transferCrawl`. Shared runtime validation rejects falsely complete, overlapping or out-of-range crawl metadata. Provider, call, record, body and request deadlines continue to bound full requests. Scope describes an acquisition request, not an ownership or exhaustive-wallet-history guarantee.

`BASE_ALCHEMY_RPC_URL` is a private engine-only fixed Base Alchemy lane. Configuration restricts its production hostname, validates DNS alongside other providers and rejects Vercel or public-prefixed deployment exposure. The read-only transport permits `alchemy_getAssetTransfers` only on Alchemy or explicit loopback test fixtures. Token/native readers use fixed filters, bounded pages/cursors and exact identity/range/order checks; active cursors never advance to a different source. Core charges index queries and its chain/pinned-header handshake to the shared allocation. Index amounts are discarded in favor of canonical receipt/transaction proofs. Index exhaustion cannot exclude omissions, and internal funding remains outside the implemented external-transfer scope.

Configured RPC URLs are trusted server configuration: approved HTTPS hosts, bounded public-DNS preflight, no redirects, read-only methods, a 2,000,000-byte response cap, and bounded calls/ranges. Blockscout, GoPlus and DEX metadata use fixed reviewed origins and their own body caps. RPC envelopes, receipt success, canonical block identities, pool authenticity, and exact amounts are validated. Credentials, upstream error bodies, and URL keys are not exposed. DNS preflight does not pin the actual fetch connection; trusted hosts and operator egress policy remain necessary.

The optional direct-creator funding query uses that same private Alchemy source and existing counted funding allocation. It accepts only the canonically attributed direct deployment sender, fixed external-native filters, the pinned full-scan range and at most two 100-item pages. Every candidate is checked against its canonical transaction, receipt and block; only positive successful native transfers to the declared pinned EOA cohort with empty historical code become retained evidence. A page failure cannot leak a partial page or exhaust the reserved final canonical read. Its separately validated `creatorFunding` coverage cannot upgrade recipient inbound-history coverage, establish ownership, or claim internal/indirect funding or independent index completeness.

Without a Blockscout key, GoPlus discovery requests only the fixed Base token-security endpoint, with a 12-second default deadline, 1 MiB decoded-body cap, no redirects or hidden retries, and exact token-result identity validation. Optional GOPLUS_ACCESS_TOKEN is a server-only bearer credential confined to the engine in hosted mode; deployment preflight rejects it on Vercel or under NEXT_PUBLIC. Reported holder counts, creator labels and nine yes/no/unknown contract checks remain untrusted source context. Source balances/percentages cannot replace pinned RPC verification; no check establishes ownership, a full audit or safety. GoPlus attribution/access/license conditions remain operator obligations, not production permission established by a successful anonymous probe. [Access and attribution](data-sources.md#goplus-verified-holder-context-and-candidate-source)

RPC fallback is explicit and limited to two distinct configured alternatives. Transient network/request-timeout/throttle failures can retry; HTTP 403 or method-not-found can recover only through a configured next endpoint, never by repeating the same forbidden request. Every physical read and fallback chain/range handshake shares the phase/total budget. Already-pinned block numbers, hashes and timestamps must agree before replay. One funding-boundary recovery can use its new allocation after a transfer-phase throttle, only if the entire handshake and a funding read fit without borrowing the final-check reserve. Only a successful verified handshake clears that throttle. Wrong-chain, malformed or conflicting evidence, outer cancellation and exhausted capacity do not become availability fallback. Public provider labels reveal a scan-wide source set, not credential-bearing URLs or independently corroborated facts.

`BASE_LOG_RPC_URL` optionally selects one independent log-discovery endpoint under the same HTTPS/host/DNS/read-only/body/deadline rules. An unavailable explicit log destination fails preflight; a healthy state destination does not bypass it. Core separately checks its chain and pinned range before use, charging the shared budget. Its access/throttle failure does not poison state reads. Only explicit `eth_getLogs` range/result-size limits or the bounded response cap enable chunk splitting; HTTP 429 and recognized quota/rate messages remain throttles, and integrity failures remain terminal. Configured log access belongs only on the protected engine; Vercel/public-prefixed configuration is rejected.

After one actual log-query HTTP 403 from a verified independent lane, core can traverse only the still-unvisited newer chunks once, newest first. The refused range is never replayed or shrunk; all original endpoint, phase/total call, deadline and canonical-reserve limits remain. The next generic availability/access failure stops that pass. Receipt/header failures or an unsuccessful log-source handshake cannot trigger it. Retained observations do not remove the explicit gap or upgrade partial coverage.

The optional SQD evaluation adapter posts only to the fixed HTTPS Base finalized-stream endpoint, with no redirects, owned fetch/body deadlines, strict UTF-8/JSONL validation, at most 128 recipient addresses and 1,000 headers, an 8 KiB request and 2 MiB decoded response. Each index request also consumes the shared acquisition budget. Contiguous page headers are validated before first/end RPC anchors; retained funding requires exact RPC transaction/successful-receipt agreement and canonical/code checks. Events, exclusions and coverage commit per fully verified block. A request's own timeout becomes recoverable `UpstreamFailure`, preserving earlier committed blocks or permitting the bounded native fallback if none completed. Parent scan abort/deadline keeps its exact reason and remains terminal; it never starts another acquisition path. Integrity disagreement also remains terminal.

An index can omit an event while returning valid headers. Completed SQD search therefore states its indexed scope and omission caveat; it does not prove an unfunded wallet, human ownership, EOA identity, complete internal history or lifetime-first funding. The actual helper passed one known-positive historical block at **06:30:30.517 UTC**, using nine bounded HTTP reads in 4.535 seconds; this is narrow positive-path verification, not an omission, hosted-operation or broad quality assessment. Its operator artifact contains metadata only; no report, raw evidence, AI, database or quota access participated. Public/Testing SQD access is development/evaluation only. `VERCEL=1` configuration and the offline production-engine preflight reject `sqd-public-testing`; no commercial SQD integration is configured. [Recorded helper scope](provider-verification.md#positive-production-sqd-helper-check), [SQD access restrictions](https://docs.sqd.dev/en/portal/pricing)

Fresh nonce CSP, request-time HTML, private/no-store responses, escaped structured data, MIME/frame restrictions, referrer policy, and restricted browser capabilities remain enforced. Do not cache nonce-bearing HTML or add inline HTML styles. Browser reports/snapshots render escaped text; explorer links use a fixed origin and validated hashes.

Wallet account state uses the same read-only transport and pinned finalized block, including `eth_getTransactionCount`; it is outgoing nonce, not complete lifetime activity. V2 pool authentication uses the fixed official factory and reverse pair lookup. Purchase/initial-liquidity annotations retain complete same-receipt supporting transfers and reject trimmed or conflicting consideration. Native-wrap attribution additionally requires the official router, exact canonical transaction value and matching WETH Deposit during acquisition. Float exclusions require retained authenticated pool identities and pinned balances. Displayed score bounds and warning gates cannot turn incomplete activity, relationships or source-reported creator labels into ownership or calibrated probabilities.

The visible References section uses a fixed BaseScan token URL, validated fixed-source DEX metadata, a fixed GoPlus Base token URL and the internal evidence ledger. External links use opener/referrer protection and are navigation only; the app does not crawl them. Readable evidence keeps exact explorer destinations while abbreviating identifiers; raw upstream payloads, internal provenance JSON, model IDs and debug receipts are absent from normal report/chat presentation. Complete validated records remain in the request-owned report and explicit browser snapshot. Source links and check times do not establish ownership, safety, source independence or a stored raw-receipt archive.

Downloaded SVG report cards escape metadata as XML text and contain no chat capsule or conversation. Token share links carry only the validated Base contract address, prefill the form, and never automatically acquire data or identify a saved report. Activity replay displays cumulative retained observations inside the declared token window; earlier funding evidence is excluded from this replay rather than relabeled as holder history.

## Optional source access and privacy

SWARM requests use only the fixed `https://swarmengine.tech` origin, reject redirects and credentials, validate bounded JSON and start one fresh request-owned scan before bounded event/result polling. No cached-result/history fallback exists. Token/chain identity and response shape must validate before attachment. Reliably stale results reject. Missing or inconsistent source clocks remain visibly unverified; a new job alone does not prove refreshed source data. The user-selected primary presentation uses one validated SWARM snapshot for its score, verdict, category points, weights, market and holder cohort, preserving source authority/time. It does not mutate or upgrade independent local evidence, balances or proof. Source graph arrays are bounded to 256 holders, 2,048 links and 256 clusters; group IDs, flags and source fractions are reported observations, not ownership or exact on-chain balances. A validated source pool identifier accepts 20-byte addresses or 32-byte pool IDs only as context, never as an RPC-call destination. An unavailable source yields a safe enum-backed human reason and a missing primary assessment, without upstream error bodies or local substitution. SWARM auxiliary APIs such as Council, DNA, wallet X-ray, replay, radar and cabals are not active integrations.

Optional Bubblemaps/Nansen transport uses fixed reviewed origins, no redirects, private header credentials, a 4 KiB request limit and a 2 MiB decoded-response cap. Owned timeout/cancellation covers headers and streamed bodies. `BUBBLEMAPS_API_KEY` and `NANSEN_API_KEY` are rejected under `NEXT_PUBLIC_` names or on the Vercel web tier; hosted keys belong only on the protected engine. Each source has explicit access, throttle, timeout, invalid-response and unavailable states. A missing key means not configured, never a clean check or invented response. Address leads and source labels remain unverified until the applicable local proof is actually acquired. Source relationships are not automatically receipt-backed wallet links.

Optional-source failure is nonblocking for independent local acquisition and analysis. Parent cancellation remains terminal, and an optional source does not bypass local evidence-integrity checks, call budgets or final canonical verification. Upstream error bodies and keys are not returned. Successful API access does not establish licensed production, redistribution or commercial use: operators must review their account's service rights before enabling it. Arkham remains rights-required; RugCheck is unsupported for this Base adapter. Honeypot.is is not called because its published terms restrict third-party exposure and primarily competing products. A supplied key does not override those restrictions. [Honeypot.is API terms](https://docs.honeypot.is/terms)

Calling these services discloses the public token and sometimes bounded candidate addresses to an external operator. SWARM may retain its own job/results, and each provider's logging/retention terms apply. TraceForge saves no server report/evidence/chat history, but that boundary is not a promise that upstream providers retain nothing. Provider keys, private visitor data and conversation are not sent to discovery services. Optional Gemini inference has its separate conversation data flow below.

SWARM polling/result reads share at most one extra GET attempt for a native network failure or HTTP5xx, preserving the same job/cursor and original deadline. Fresh-scan POSTs, rate/access limits, invalid data, stale results and identity mismatches are never retried. Native fetch failures retain the availability classification; decoding failures remain invalid responses. Public status copy uses only the finite validated reason.

The exit-quote lane uses counted, bounded read-only RPC calls at the pinned finalized block and fixed official Base pool/quoter identities. V2 calculation retains exact reserves; V3 verifies the quoter factory and fixed ABI shape. Conflicting pool/block/protocol identities fail integrity validation; unavailable or exhausted optional calls leave an unknown quote. No transaction is signed or broadcast. A quote is not a transfer simulation, approval/tax/restriction check, proof of full V3 input consumption, successful sale, multi-pool route or guaranteed exit price.

## Database and validation

Remote MySQL requires certificate-verified TLS and hostname identity; remote plaintext is rejected. Loopback is the explicit local exception. Separate runtime/migration accounts remain in the verified local setup; VPS engine environments exclude both. Migrations use a dedicated advisory-locked connection and never run at build/startup/request time.

Ten genuine integration tests passed on local MariaDB 10.4.32, including admission-only concurrency/no saved work and legacy compatibility. Signed-context unit tests cover tampering, expiry, bounds, citations, cancellation, and deadlines with injected inference. These results do not verify hosted grants/TLS, Linux resource behavior, live new-flow quality, or internet abuse resistance. Deployment load, body/log hygiene, dependency maintenance, backups of remaining legacy data, and real-origin HTTPS/CSP checks remain separate work.

## Optional external inference

`INVESTIGATOR_AI_PROVIDER` selects `auto`, `local`, `openrouter` or `gemini`; explicit selection never calls another provider. OpenRouter defaults to `openrouter/free` and `OPENROUTER_FREE_ONLY=true`. This policy accepts only the free router or a specific `namespace/model:free`, sends zero `max_price` ceilings for prompt/completion/request, and prevents paid cloud fallback. Automatic mode may try configured local inference first but excludes Gemini while free-only OpenRouter is active. Direct Gemini remains a separate explicit opt-in; paid OpenRouter configuration requires deliberate `OPENROUTER_FREE_ONLY=false`. The policy covers inference API charges, not hosting or local compute costs.

Only availability, request-limit or timeout failures permit another selected attempt, sharing one deadline with reserved time for remaining attempts. Invalid grounding, malformed output and cancellation never trigger fallback. Every body remains bounded and abortable with unchanged canonical report restoration and complete-proof chat validation. Free model rate/access restrictions produce failures rather than automatic purchases or paid-model switches. A nonredirect HTTP 429 is classified as a trusted AI request limit without reading its upstream body. The protected engine and public scan/chat boundaries retain only the finite AI_RATE_LIMITED code and canonical message; no provider diagnostics, account quota amount or reset time are published. Evidence previews stay incomplete, and the browser asks visitors to wait for the limit to reset rather than immediately repeating the full scan.

`OPENROUTER_API_KEY` and `GEMINI_API_KEY` are private engine-only credentials, excluded from errors, browser responses, public variables and Vercel web-tier configuration. OpenRouter uses the fixed HTTPS chat-completions endpoint with Bearer authorization; direct Gemini uses its approved Google origin/model allowlist and `x-goog-api-key`. Redirects, tools, uploads and arbitrary provider URLs are rejected. OpenRouter model IDs are bounded trusted configuration. The reviewed `openrouter/free` router and `:free` suffix are accepted; other automatic routers, variant suffixes and URLs are rejected. Syntactic acceptance does not establish model compatibility. [Provider configuration](local-ai.md#provider-selection-and-openrouter-setup).

Cloud inference discloses bounded supplied context and the current question/recent dialogue to OpenRouter and its downstream provider, or directly to Google; social prompts contain no chain findings. OpenRouter requests strict JSON schema and supported parameters with upstream fallback disabled. `OPENROUTER_ALLOW_DATA_COLLECTION=false` is the default and sends `data_collection: "deny"`. Explicit operator opt-in `true` sends `"allow"`, permitting providers that may retain/use prompts and responses, including training under their policies. This OpenRouter-only choice changes no zero-price, schema, evidence or fallback controls. The operator's account-level free-model training setting is separate and is not changed or verified by this flag. [Provider policies and account preferences](https://openrouter.ai/docs/guides/privacy/provider-logging).

Neither data-policy setting is a ZDR promise; this adapter does not require zero-retention endpoints. External retention and billing remain governed by those services. TraceForge's absence of server report/chat history does not govern their records. [OpenRouter routing and data policies](https://openrouter.ai/docs/guides/routing/provider-selection).

Reports and answers preserve the actual served model ID. A free-router signed capsule binds to its configured request scope, allowing a subsequent request to use a different compatible free model; old paid-model capsules do not match that scope. Signature, profile, expiry, token/role and full-proof checks remain mandatory, and removing a provider from selection invalidates its contexts. Loaded local weights can stay warm for at most 900 configured seconds without application chat/report history. The **2026-10-14** genuine pinned NVIDIA free trial passed canonical review and greeting/funding chat on synthetic context, with approved provider data use and zero recorded API cost. Only metadata was archived. Earlier schema, privacy-policy and grounding failures remained errors. This narrow pass does not prove general semantic truth, all free endpoint compatibility, account settings, live-chain accuracy or hosted deployment. [Verification scope](local-ai.md#provider-selection-and-openrouter-setup).

Local main review permits one generated-summary correction only after the original finding selectors and complete citations validate. Only selected decision reasons enter that second local request, with unchanged selectors, reason order, model configuration, cancellation and deadline. No rejected draft, new acquisition or saved conversation is required. Invalid citations, malformed JSON and cloud responses cannot trigger this correction; invalid corrected prose still fails.

Inner generated JSON also rejects duplicate decoded keys per object, malformed syntax, nesting beyond 256 levels and content beyond 262,144 UTF-16 code units. Existing transport byte limits remain binding. Ambiguous model fields fail before schema restoration and cannot start a semantic correction.

## Direct deployment attribution

Optional `EvidenceRecord.creation` metadata records only an acquired successful direct deployment: the canonical transaction sender, null top-level destination, successful receipt status and a receipt contract address matching the investigated token. It attaches to a retained positive zero-origin token mint. Factory transactions or a mint recipient alone do not satisfy the rule. Shared analysis/report boundaries reject wrong tokens, nonmints, zero values, failed/non-direct metadata, out-of-range events, conflicting transaction inclusion and conflicting deployment senders/transactions. Independent liquidity proof may coexist on the same constructor mint.

Direct receipt-backed attribution takes precedence over GoPlus while disclosing a conflicting source-reported address. It establishes a deploying address, not developer identity, ownership or present control. The bounded lookup shares provider/time/call limits and does not introduce arbitrary URLs or a new credential. Missing or exhausted lookups retain unknown attribution. Compact AI and signed chat preserve the actual retained evidence reference and creator role; deployment answers require that proof. Existing schema-v1 reports remain compatible without the optional annotation. Request-owned data lifetime is unchanged.
